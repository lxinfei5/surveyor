# Surveyor — 看清全局，溯本清源，深入搜索，分工协作

在授权与事实边界内，对问题是否被正确解决承担判断责任。

本方法有四个方向。看清全局负责空间覆盖，溯本清源负责目标正确，深入搜索负责用证据推进，分工协作负责让多方判断相互校验、衔接并积累。

四个方向相互校正。先形成可用的全局轮廓，再深入一个分支；新证据可以改变目标解释或树的结构。协作贯穿这些判断，各分支仍须独立完成必要的取证与验证。无需等到穷尽所有细节才开始验证。

开放探索也可以先从材料形成值得追问的问题。四个方向既帮助解决已有问题，也帮助连接旧材料、修正理解；不要求固定阶段或每次启动多个 Agent。

## 何时使用

- 设计架构、分类、路由、责任划分或新的工作方式。
- 评估新增、删除、重构或不同方案的取舍。
- 用户的问题包含未经核验的前提或指定手段。
- 复杂排障、研究探索或多轮尝试仍未推进。
- 从新旧材料寻找尚未提出的问题、机制或联系。

目标明确、影响小的执行任务直接完成。不要为每次小改动建立问题树。

## 共同前提：审视工作环境与任务是否匹配

开始开放探索、工作阶段变化，或思路反复被同一框架截断时，按需检查相关项目说明、`AGENTS.md`、技能、工具和上下文。它们是否把问题强塞进已有模块，要求未成熟想法立即成为已证实的实施结论，或让所有执行者只能复述一个解释？只查影响本次判断的部分，不把环境审计变成每个任务的固定前置流程。

发现不匹配时，指出具体规则或能力缺口、来源、适用范围、原本保护的条件，以及它怎样妨碍当前目标。核对实际生效的指令与授权，区分必须保留的边界和可调整的项目惯例；不能因为不便就自行缩窄规则含义，也不能把当前环境做不到当成现实无解。

提出保留保护职责的最小适配，例如澄清探索与实施的适用范围、调整局部模板或在获准范围内选择更合适的环境。已有授权覆盖的调整直接完成；未覆盖的修改先给出可审阅的具体变化、影响范围及恢复方式，再取得授权。可继续不依赖该调整的工作。Surveyor 不授予额外权限，换目录、工具或模型也不能绕过仍有效的限制。

调整后用本次任务检查实际效果：原先被误排除的有依据线索是否能进入探索，未知是否仍明确，必要的验证和保护是否保留。文件改写不等于环境已适配；相关执行者也须按第四方向更新其判断。具体见[真实诉求中的环境适配](references/real-intent.md)。

## 本地恢复状态

复杂、长程或多分支任务，在深入验证前必须按[本地状态与恢复](references/local-state.md)建立可发现的本地状态；已有任务文件满足要求即可复用。一次简短回答无需制造日志。

目标与逻辑树、当前路径、已否定范围、受阻/暂缓/未探索方向、证据、动作结果及下一动作不能只存在于对话上下文。关键变化、回退后继续前、压缩或交接前，必须实际写入并重读核验；不要把“稍后记录”当作完成。无法可靠写入时，说明具体限制，暂停依赖该记录的深入探索。

中断、压缩或换会话后，先读取落盘状态，复核目标、授权和输入版本变化，再从有效分支继续；没有新依据不重试已失败路径，不把局部否定扩大为全局否定。

只保存可复核的证据、结果、结论和简短决策依据，不保存隐藏思维链。运行资料留在任务本地，不进入公共 skill 仓库，不含密钥，未经另行授权不上传；普通本地文件不等于跨机器的永久备份。

## 方向一：看清全局，遍历逻辑空间

先明确本次要解释或改变的对象，再画出问题空间。现有工具、目录和习惯只能提供线索，不能定义空间边界。

项目规则和工具能力也属于环境条件；检查它们是否造成观察盲区或预先排除候选解释，不能据此把真实问题缩成当前项目能表达的形状。

1. 写出当前根问题及适用范围。
2. 列出影响结果的阶段、对象、条件和参与者。
3. 按同一种问题拆分每组同级分支。
4. 标出分支之间的依赖、组合和优先关系。
5. 用边界案例查找重复、遗漏和错误拆分。
6. 把未解释的现象保留为扩树线索。

同级分支要有一致的拆分依据。来源、访问条件和工具是不同维度；它们之间也可能存在依赖。分类不同不代表相互独立。

需要唯一归属的分类或路由，应给每个案例指定主责任方。未知和不适用要写明原因。研究假说可以重叠，也可能共同成立。

树是搜索视图。共享依赖应引用同一个节点，统一来源和版本，避免各自副本静默漂移；该节点可以保留尚未解决的证据冲突与竞争解释。多因素共同作用时，标明“同时满足”；替代路线标明“任一满足”。

先遍历主要分支，检查空间形状，再沿关键分支深入验证。未访问的分支要保留，不能因为当前路径顺利就删除。

每次全局检查都要考虑四种反例：重复归属、没有归属、边界切换、失败路径改变任务语义。

开放探索中，新证据、解释冲突、相似机制或条件变化，都可以触发对相关旧材料的回看，发现新问题、重组分支或重审根问题，不必等到已知树耗尽。说明这次多看见了什么、依据是什么；换一种摘要不算新增理解。参照用户已有认识判断价值，不把“对用户有启发”夸成世界首创。

尚未成题的片段和弱联系可保留为线索，不必立即证实或强行归树。清楚区分观察与猜想；准备据此作结论或采取行动时，再转成可验证假设。明确执行任务中的旁支可简短留下，不自动扩大本次任务。

详见[逻辑空间](references/logic-space.md)。演示见[取证空间覆盖](examples/01-global-space.md)。

## 方向二：溯本清源，核验真实诉求

把用户的问题作为理解目标的起点。用户给出的原因或手段可能不成立，需结合证据核验。

区分四件事：用户看到的现象、用户提出的解释、用户指定的手段、用户希望得到的结果。它们不能相互代替。

1. 从当前请求和上下文提取期望结果。
2. 找出会改变方案的隐含前提。
3. 用现有证据检验这些前提。
4. 必要时提出一个能区分关键诉求的问题。
5. 将已确认的结果写成根节点的验收条件。

“真实诉求”是待核验的解释。不要把自己的偏好当作用户目标。用户未明确的价值取舍，应保留为待确认项。

若用户明确把某种手段列为约束，就在该约束内求解。发现冲突时，解释冲突并请求裁决。目标尚不清楚时，可继续不依赖该取舍的取证。

有了可观察目标，再判断当前最值得作用的约束。比较做、不做、少做、换一种做法，计入验证、返工和维护成本。

证据不足时保留竞争解释。不要为了指定唯一主因而编造确定性。收益、成本和授权共同决定是否采取行动。

把想法转成指标、代码或试验时，核对保留了哪些对象、条件和目标，舍弃了哪些含义。代理指标可以用于局部验证，但不能静默代替原问题；用户纠正时，先检查是否发生了这种替换，而非只改措辞。

若本次目标是形成理解或发现值得追问的问题，可按这个目标验收，不强制改成行动方案。Agent 可以提出排序与取舍建议；用户保留的思想方向裁剪和价值选择，不能由局部取证排序代行。

详见[真实诉求](references/real-intent.md)。演示见[从加并发追溯诉求](examples/02-real-intent.md)。

## 方向三：深度优先，假设验证、回退与扩树

在全局轮廓中，优先深入最能推进目标的分支。排序依据包括解释力、区分价值、失败代价和验证成本。

深度优先要求沿当前路径推进到可验证的结果。不要在多个分支间只换说法、浅尝即止。

### 节点假设

每个影响决策的节点都要能回答：

- 当前假设是什么，它依赖哪个上级前提？
- 什么观察支持它，什么观察会否定它？
- 下一步取得哪项证据，或验证哪个必要条件？
- 当前是待验证、已支持、已否定，还是受阻？

可以暂时进入一个待验证的条件分支。此时下游结论都带有该前提，不能提前作为最终事实。

探索线索进入验证时，指出它改变了哪个解释或前提，以及哪项观察能将它与已有解释区分开；沿用这些节点要求，无需另建线索分级制度。

### 沿分支深入

1. 从当前节点选择最有价值的未决子节点。
2. 执行获授权的取证或验证。
3. 根据结果更新节点状态。
4. 假设受支持时，继续验证其必要子条件。
5. 获得候选解后，核验根目标和关键反例。

支持一个假设不等于完成任务。替代路径中一个候选解可能足够；共同必要的条件则必须全部满足。

### 失败后回退

假设被否定时，先回到父节点。若父节点仍可成立，选择它的剩余分支。

若证据也推翻了父节点，继续向上回退。停在最近仍成立且有可推进分支的祖先。保留独立证据，撤销依赖错误前提的结论。

访问失败、权限不足或证据缺失只表示受阻。受阻分支可以暂挂，但不能标成已否定。先推进不依赖该缺口的分支。

回退不等于撤销真实操作。若试验留下副作用，先确认当前状态，再决定恢复或保留。恢复也须符合授权与可逆性要求。

### 已知树耗尽后扩树

目标仍未达成，而已知分支都已处理时，先怀疑树不完整。启动结构检查，再继续搜索；不要直接宣称现实无解。

1. 复核根问题是否把用户提出的手段当成了目标。
2. 检查是否遗漏了上游、下游、时间或环境条件。
3. 检查拆分依据是否排除了组合原因。
4. 用未解释的现象寻找新的可区分假设。
5. 将新分支接到正确的上级节点后继续深入。

“树不完整”是优先工作假设，不是已被证明的事实。若已有证据证明约束矛盾，应交付不成立的原因。若关键分支只是受阻，应交付具体缺口。

有效扩树必须改变解释范围、关键前提或验证方式。改名、重复同一失败请求，均不算新增分支。

### 何时继续，何时收束

目标未达且仍有有价值的授权内路径，就继续推进。目标已达且必要验证通过时，不必继续验证无关分支。

目标未达且树已耗尽时，先完成扩树检查。只有约束冲突、不可取得的条件或明确成本限制，才能据此收束。说明已成立的结果、剩余缺口和重新启动的条件。

不要在没有证据变化时重复旧路。持续产生子问题却没有新增证据时，回查拆分依据或验证方式。

详见[深度优先搜索](references/depth-first-search.md)。演示见[报表迟到排障](examples/03-depth-first-search.md)。

## 方向四：分工协作，共同校正

围绕问题分支、竞争解释或验证需要组织协作，明确各执行者负责的范围、共享依赖及谁整合结果。是否并行、采用哪些模型，取决于能补足什么观察、判断或执行能力及其成本；简单任务可由一个 Agent 完成。

共享目标、边界、输入版本、带来源和适用范围的证据，以及必要的分支状态。各执行者可以独立形成解释，再比较其预测与依据；不要求先接受整合者的初步结论。使用任务已有入口和材料，不默认各方拥有相同上下文、工具或访问能力。

分歧先核对是否讨论同一对象、版本、时间窗和验收条件。范围不同则分别保留；确有冲突则保留各方依据与下一项区分证据，不靠多数意见或模型名称裁定。证据独立性来自来源和观察过程，同源材料被多次转述不增加独立支持。

关键纠正或反证出现时，定位受影响的分支，通过已获授权的协作渠道通知。接收方继续依赖该前提的工作前，应核对新版依据，修改相关结论、产物和下一动作，或提出有证据的异议。以这些实际变化核验生效；“已发送”“收到”不足以证明理解更新。尚未确认应用时保留缺口，暂停依赖旧结论的推进，独立分支可以继续。

环境或规则适用范围发生获准调整时，同样更新共同依据并核验相关分支的实际应用。多个 Agent 共同受限于一个狭窄模板，不能仅靠增加执行者数量获得独立探索。

整合时寻找跨分支的新联系：一方的新证据能否解释另一方的旧材料，或暴露共同前提的问题？标明联系的来源与不确定性，按前述规则进入验证或保留为线索。纠正揭示的区别可传给相关分支，由接收方检查本场景的适用条件；共享一句原则不等于已经掌握。

协作仍以根目标验收。分派完成、结果汇总或全员同意，均不能代替必要条件验证。共同记录及恢复方式见[本地状态与恢复](references/local-state.md)，协作演示见[报表迟到排障的延伸](examples/03-depth-first-search.md)。

## 四个方向如何联动

全局空间发现遗漏时，补充或重切分支。用户前提被推翻时，修正根问题及受影响的分支。节点验证失败时，回退；已知路径耗尽时，重新检查空间。

目标、授权、身份、来源和证据等级不能在换路时静默改变。局部更快或步骤更少，不能代替目标达成。

收到纠正时，先修正当前结果及依赖它的结论，再辨认混淆了什么、这个区别何时重要、何时不适用。将有依据的区别用于新场景，并检查条件和反例；局部偏好或一次失败不能直接升级为通用禁令。是否学会，要看后续任务能否独立识别同类区别，不能以增加规则或记住原话代替。具体见[真实诉求](references/real-intent.md)。

## 交付

给用户可复核的摘要：当前结论、关键证据、下一步及剩余缺口。必要时展示简化问题树或验证记录。

开放探索按需说明新增理解、连接了哪些旧材料、哪些仍是猜想及为何值得追问。当前交付可以是有依据的新问题，无需证明它已有解，也无需把每条线索变成待办；收束仍以本次约定目标为准。

验证记录只保留假设、观察、状态和结论变化。不要输出内部思维链，也不要强制用户阅读全部搜索过程。

交付前按[自检清单](references/checklist.md)复查。主文和参考指导判断，不要求固定报告格式。

# Surveyor — 先照清全局形状，再动手

> **一句话：** 面对一个值得想全的问题，先把它**铺成一块完备、可遍历、有唯一 owner 的逻辑空间**，证明你没漏；再用**第一性原理**在其中裁决主次与不可交换的边界；最后用**反例**攻击自己的空间，并产出一份别人能复核的交付形状。
>
> 这是一个**同时成立的形状契约，不是 1→2→3→4 的流水线**。它约束你**必须想完并自检**五件事，不规定你内部按什么顺序思考。顺序可以跳跃；**默认对外输出按主次分层**，不是把五件事平铺成等权五章。

---

## 何时用 / 何时不用

**用（高杠杆、值得想全）：**
- 结构设计 / 架构评估 / 重构 / 新增目录、入口、阶段、能力、回路。
- 设计分类、路由、矩阵、枚举、状态机、决策流程。
- 拆解一个多因素纠缠、方案空间不显然的复杂问题。
- 评估「该加还是该删」「该先修哪个」「这个改动值不值」。
- 被问「这东西能做什么、不能做什么」的边界判断。

**不用（杀鸡用牛刀）：**
- 一句话能定、单点、可逆、影响面小的改动。
- 纯执行类任务（命令怎么跑、语法怎么写）——那是操作手册，不是本方法的对象。
- 已经有人在更高层把空间与主次定好、你只需填局部实现时。

> 判据一句话：**这个决定如果做错了，会不会要返工、会不会牵出第二个真源、会不会影响长期演进？** 会 → 用本方法；不会 → 直接做。

---

## 形状契约（五件事，缺一不可）

### 1. 第一性裁决 —— 先定方向与主次

动手前先给出四件事。这是从终局目的**一层层追问到不能再约简**的因果判断，不是「我偏好什么」。

- **终局目的：** 最终要改善哪一个可观察的结果？禁止「完善系统」「优化体验」这类不可证伪的套话——它必须具体到「能据此拒绝一个无关优化」。
- **当前主矛盾：** 此刻**最影响终局结果、且本次可作用**的那一个变量/约束/瓶颈是什么？为什么它比其它项更上游、波及面更大、或失败代价更高？若声称两项并列，须说明它们为何因果耦合、无法分开裁决。*（注意：主矛盾必须是「可作用」的杠杆；那个影响最大但本次动不了的因子——如外部政策、市场时机——不算主矛盾，应列入不可交换边界或环境约束。）*
- **不可交换边界：** 哪些性质即使能换来局部便利也**不能牺牲**（单一真源、语义不被实现改写、真实身份不冒充、人的最终裁决权）？实现可换，边界不可偷换。
- **优先级依据：** 明说本次排序主要受哪些影响支配。候选轴包括（**不是固定等权打分表**）：终局效果、因果上游性、波及面与复发频率、失败代价、长期防腐与单一真源、长期演进与可扩展性、可逆性、运行环境现实、复杂度与上下文债。**不预设谁永远第一**——长期防腐只是重要候选，须现场判断当前谁最支配结果。

**主矛盾判别器（不是等权评分）：** 做一个反事实——*若本次只能修一项，修哪项最能改变终局结果？* 再追问三层：① 哪项一旦错，会让其它优化**整体失效**？② 哪项位于**因果上游**、错误会向最多下游传播？③ 哪项会**跨会话复发、难逆、或产生最大长期债**？由此具名**一个**当前主矛盾。其它影响仍进入边界与次要项，**不因没排第一而消失**。若反事实答案撞上不可交换边界，**边界优先**。

> **合法出口（防死循环）：** 主矛盾通常是**一个**；允许两种例外，但都**必须经判别器逐项验证后具名理由**，不得偷懒平铺——(a) **耦合并列**：两项因果耦合、无法分开裁决，须说清耦合机制；(b) **无支配项**：问题地形客观上是平的（多因素近似等权），逐项验证后确认无一支配，则如实输出「无单一主矛盾 + 理由」，再按波及面/失败代价给次要项排序。**「找不到主矛盾」不等于「形状做错了」**——只有没跑判别器就放弃，才算形状错。

**主次裁决：** 先修「违反终局目的/不可交换边界、且位于因果上游会向下游扩散」的问题；再修覆盖缺口与边界冲突；最后才是工具顺序、措辞、局部体验。**任何局部优化若会增加双源、耦合、静默路由或未来迁移成本，必须把这笔长期账写进裁决，不能只报眼前收益。** 暂不修的次要项也要**具名**，防止「没写 = 没看见」。

### 2. 逻辑空间 —— 证明覆盖、互补与最小

方向定了，问题空间须能回答下面六问。这是「证明你没漏、没重、没藏」的完备性论证。

- **原子对象：** 一行/一格/一项究竟在分类**什么**？平台、页面、工具、状态等不同对象**不得偷混**在同一格里。
- **同类型逻辑轴：** 每个轴只回答**一种**问题。先分别在**轴内**检查完备/互斥，再看轴与轴的关系。**普通 MECE 不能替代「先分类型」**——把不同性质的东西并列，是最常见的假完备。
- **关系形状（关键，别再全叫「正交」）：** 轴与轴、项与项之间，要分清是 **同轴分区**（同一维度不重叠切片）、**正交叠乘**（一轴取值不限制另一轴的合法集）、**约束/依赖**（一轴取值会收窄另一轴的合法集，如「需登录」让某些实现失效）、**优先级**、还是 **override**。**检验是否真正交：换一轴的值，会不会强迫另一轴跟着变？会 → 不是正交，是有依赖没拆出来。** 禁止把「B 借用 C 的访问通道」误写成 B/C 同义，也把「约束」误标成「正交」。
- **唯一 owner 与空间闭包：** 每个合法原子案例都有**一个主 owner**，或显式标 `N/A` / `UNKNOWN + 原因` / `未覆盖 residual`。**不得靠「其它」「看情况」隐藏零命中。** 这是**覆盖论证**（枚举 + residual 兜底），不是数学保证——开放问题空间无法真正证完备，诚实做法是「给出覆盖论证 + 显式标出未覆盖处」。
- **互补与最小：** 每一项都要能指出一个**其它项覆盖不到的具体案例**；删掉它若没有案例失去 owner，这项就是冗余。两项若回答同一问题，**合并**，或声明边界/优先关系。*（例外：**刻意的冗余**——备援、双活、backup owner——须显式声明为「冗余设计」，不占同轴主 owner 名额，不误判为冗余。）*
- **相互干扰：** 标出子项之间的耦合、替代、侵蚀与长期副作用。**局部最优若破坏上游不变量或另一轴的语义，按第一性裁决退让。**

### 3. 反例审查 —— 攻击自己的空间

任何结构性交付，至少用以下四类反例攻击一次：

- **双命中：** 有没有合法案例**同时落到两个同级 owner**？（= 分区有重叠）
- **零命中：** 有没有合法案例**落不到任何 owner**，只是被表格/分类静默省略了？（= 分区有洞）
- **边界切换：** 哪个**可观察条件**会让案例从一类切到另一类？这个切换条件写清了吗？
- **失败穿透：** 当原生能力 / 登录态 / 数据源 / 依赖**不可用**时，fallback 是否**偷偷改变了任务语义、对象身份或证据等级**？

> 高影响、难逆的改动，可另起一个**干净上下文的独立视角**：只看终局目的与边界、**不看现方案**，独立推一遍主矛盾与逻辑轴，再与当前方案对照。这是**按需红队**，不是常驻编排，也不以多数票替代最终裁决。

### 4. 交付形状 —— 正确且低心智负担

对外只交付**可验证的摘要**，不暴露内部思维链。五件事是**作者侧必须想完并自检**的契约，不是**默认全部展开**的报告模板。

**对输出本身也做第一性与逻辑空间：**
- **读者终局：** 在最低心智负担下，拿到**正确且可复核**的裁决（信什么、先做什么、别踩什么）。
- **读者主矛盾：** 默认只钉「结论 + 当前主矛盾 + 动作次序」；其余凡**删掉不改变裁决**的，简述或标「问则展开」。
- **输出空间唯一 owner：** 每层只回答一种问题——L0 给裁决与动作，L1 给会改裁决的骨架与反例结论，L2 给可复核细节。禁止五件事等权平铺（那是输出上的假完备）。
- **删 > 加（对篇幅）：** 完整轴表、逐项互补证明、四攻逐条构造、break_condition 勾选清单——**默认不进正文**；作者可在 checklist 侧完成。

#### 默认输出骨架（字段固定，正文可短）

默认交付 = **整块骨架**（L0 必满槽；L1 必有「空间 + 反例」；L2 可一行）。**按此标题与顺序写**，不要改成五件等权章节，也不要另起长篇散文代替骨架。

```markdown
## 裁决
- **结论：** …
- **终局：** …（一句，可证伪）
- **主矛盾：** …（具名 + 为何支配；耦合并列 / 无支配项须写明）
- **先修：** …（一句理由 / 长期账可附半句）
- **后修：** …（具名从简，一行）
- **暂不修：** …（具名从简，一行；禁止省略）
- **边界：** …（只列会改本次裁决的；无则写「无额外边界」）

## 关键支撑
- **空间：** 主轴；关键关系（正交 / 依赖 / 借道…）；关键 owner / residual
- **反例：** （二选一）
  - 无阻塞洞 → 一行收口，如：`四攻已过；无双/零 owner、无失败穿透；边界切换已钉清`
  - 有洞 / 修补 → `洞：… → 收口：…`（可多条，仍保持短）
  - 若启用红队 → 仅附 `红队分歧：…`（不报完整平行推演）

## 可展开
- **次要：** …（问则展开）
- **break_condition：** 未命中 | 命中：…（须重做形状）
- （可选）全表 / 四攻构造 / 优先级细节 → 问则展开
```

**槽位规则（约束格式，不改思考）：**
- L0（`## 裁决`）七个 bullet **槽位齐全**；后修/暂不修可极短，**不得删槽**。
- L1（`## 关键支撑`）只写删掉会误判的；**空间**与**反例**两条必现；禁止贴全量轴表或四攻逐条构造。
- L2（`## 可展开`）默认各一行点名；用户追问再展开。
- 字段名固定用上表黑体标签；允许把「终局 / 主矛盾」写成两行，不允许拆成独立长文替代骨架。
- 极简场景仍用此三节标题；内容可以短到每行半句，**不要为显得完备而灌水**。

#### 禁止（交付退化）

- 把五件事平铺成等权五章，或用 checklist 全文当用户正文
- 反例「做过」但不落地——读者无法复核是否真打过
- 为显得完备，展开**不改变裁决**的细节
- 把后修/暂不修写没了（「没写 = 没看见」仍成立；正确做法是**具名从简**，不是省略）
- 自创另一套章节结构替代上表骨架（可用表格/加粗，但**槽位与顺序不变**）

**默认入口与收敛（这不是流水线，但有顺手的起手式）：** 默认从第 1 件（第一性）进；第 2、3 件若暴露第 1 件选错了主矛盾或切错了轴，**回第 1 件重来**；当轴不再重切、反例不再翻出新洞，即收敛。顺序可跳跃回环；**想完五件 + 按骨架写出** 才算交付。

**合格信号（读者能……）：**
- 扫一遍 `## 裁决` 即能复述终局、主矛盾、先做什么
- 在 `## 关键支撑` 上给关键案例找到 owner；知反例是否过关
- 从 `## 可展开` 知道次要项被看见、先不修，且可按需追问

### 5. break_condition —— 本方法自身的失效信号

命中以下**任一**条，说明问题形状做错了，**先重做形状、不进入局部修改**：

- 从已有工具/文件**倒推**分类（而不是从问题正推）。
- 无法具名当前主矛盾，把**所有问题平铺同权**。
- 同一轴里混入**不同类型**的对象。
- 存在**双 owner / 零 owner** 却不披露。
- fallback **改写了语义**（证据降级、身份偷换、范围缩窄）却冒充完成。
- 局部优化**增加双源或耦合**却不计长期代价。
- 只有**顺滑正例**，没有边界/失败反例。

## 三条贯穿立场（防退化）

- **整体 > 零件：** 先问一个部件**该不该存在、属于哪一平面、形态能否从终局目的推出**，再谈它的内部深度。局部更优不得换来整体更坏；若某平面**一句话说清 owner 都做不到**，先停下重构问题形状。
- **删 > 加：** 复杂度预算为负。**合并优于扩张，指针优于复制**；新阶段/新入口/新目录**默认有罪**——只有能证明它补上**不可复现的地板**，或**显著减少长期耦合**，才允许增加。*（**前置：本立场适用于已有复杂度存量的系统**——主风险是膨胀与耦合时。绿地/早期项目的主矛盾往往是**能力缺失**而非复杂度过剩，此时默认有罪的不是「加」，而是「无 owner、无法从终局推出的加」；从 0 到 1 的奠基性新增不受此压。）*
- **约束形状 ≠ 编排思考：** 本方法是**自觉执行的心智形状**，不该被固化成 schema、lint、强制 gate 或 1→2→3→4 的硬流水线。一旦做成引擎，就从「帮助想全」退化成「假装想全」。

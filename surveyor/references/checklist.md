# 四个方向的交付自检

按本次目标检查，深度与影响相称。此表用于自检，不是固定报告模板。

- [ ] 若发现任务与环境不匹配，已定位规则来源、适用范围或能力缺口及其影响，未把项目能表达的范围当成问题全貌。
- [ ] 若做了环境适配，修改在有效授权内且保护职责保留；已检查本次产物和相关执行者的实际变化，未仅凭文件更新宣布有效。

## 看清全局

- [ ] 根问题及适用范围清楚。
- [ ] 同级分支使用一致的拆分依据。
- [ ] 依赖、替代、组合与共享节点已区分。
- [ ] 关键边界案例、失败路径和未解释现象已保留。
- [ ] 分类责任的唯一归属没有强加给研究假说。
- [ ] 开放探索中的新联系有材料依据，说明相对旧理解增加了什么，猜想未冒充事实。

## 溯本清源

- [ ] 现象、解释、手段和期望结果已分开。
- [ ] 会改变方案的前提已核验，或已标待确认。
- [ ] 用户明确的约束和价值取舍受到尊重。
- [ ] 验收条件能判断结果是否服务真实诉求，指标或试验未丢失原对象与条件，新要求未覆盖仍有效的旧目标。
- [ ] 行动选择考虑了整体成本和授权范围。
- [ ] 若将纠正用于新场景，已检查适用条件和反例，未把本次偏好或局部失败变成通用禁令。

## 深度优先搜索

- [ ] 关键节点有假设、否定条件和下一项区分证据。
- [ ] 已支持、已否定、受阻和未探索没有混用。
- [ ] 失败后回退到正确上级，并保留独立事实。
- [ ] 必要条件失败与替代路线失败得到不同处理。
- [ ] 目标未达且已知树耗尽时，已检查并尝试扩树。
- [ ] 新分支带来新的解释或验证，而非改名和重试。
- [ ] 深入过程没有陷入无证据的无限细分。

## 分工协作（有多个执行者时）

- [ ] 分工对应问题需要，责任、共享依赖和整合入口清楚，各分支仍完成必要取证。
- [ ] 同源材料未重复计作独立支持；分歧的来源、范围和待区分证据保留，未以多数意见替代验证。
- [ ] 关键纠正已体现在受影响分支的结论、产物或下一动作中，或明确保留异议与应用缺口。
- [ ] 跨分支新联系有出处和不确定性；独立探索及未受影响的事实得到保留，分享未扩大授权。

## 交付与边界

- [ ] 复杂、长程或多分支任务已按[本地状态与恢复](local-state.md)实际落盘并重读，入口和证据引用可定位。
- [ ] 从文件可恢复目标、授权与输入版本、当前路径、否定范围、受阻/暂缓/未探索方向及下一动作。
- [ ] 运行资料未混入公共 skill 仓库；记录不含密钥，上传或备份未超出授权。
- [ ] 按本次根目标验证交付及关键反例；发现问题与解决问题没有混用，缺口已说明。
- [ ] 换路未静默改变目标、身份、来源和证据等级。
- [ ] 回退后的实际副作用已核查。
- [ ] 用户能看懂结果、依据、风险与下一步。
- [ ] 收束原因明确，没有把树耗尽当作无解。

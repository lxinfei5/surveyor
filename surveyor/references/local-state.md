# 本地状态与恢复

本参考维护[主文](../SKILL.md)的落盘、共享与恢复约束。它为四个方向保留可恢复的工作状态，不增加数据库、服务或专用框架。

## 建立可发现的入口

复杂、长程或多分支任务，在首次深入验证前创建或复用本地状态文件。先搜索任务已有的计划、日志或交接文件；若已能恢复下述内容，就直接更新，不另造一套。

没有既有约定时，可在任务工作区使用 `.surveyor/<任务标识>/STATE.md`，将证据放在同目录或引用已有文件。多个任务各有独立标识。首次向用户报告该路径，并在已有任务入口或交接文件中留下路径；采用其他位置时，也要能从工作区入口找到它。不要只在对话里留下一个外部路径。

运行状态不写入 skill 安装目录或公共 skill 源码仓库。若任务本身就在公共仓库中，使用仓库外的本地任务目录；需要入口指针时，用本地忽略文件并核验不会被提交。交付前检查暂存内容，只发布通用规则和虚构示例。不得将实际运行状态或私人证据混入 skill 发布，也不得未经明确授权上传或备份。状态文件不得保存密钥或原始私人会话；已获授权的独立备份按指定目标及范围执行，并核验实际保存结果。

普通本地文件只保证当前存储仍可访问时的恢复，不承诺跨机器或磁盘丢失后的永久备份。另行备份遵循用户授权。

## 最小恢复内容

格式自由，一个 Markdown 文件通常足够；较大的树或证据可以拆文件，但入口必须指向当前有效版本。

| 内容 | 恢复时必须能回答 |
|---|---|
| 目标与边界 | 用户期望的结果、验收条件、根问题和范围是什么？哪些约束、授权、持续时间/停止条件及待确认取舍仍适用？ |
| 输入基线 | 依赖哪个文件/数据/代码/规则版本、来源和时间窗？如何发现它变化了？ |
| 逻辑空间 | 节点标识、父子关系、共享依赖，以及“任一满足”或“同时满足”的关系是什么？ |
| 节点判断 | 假设及范围、支持/否定条件、状态、证据与结论是什么？否定只影响哪些节点，什么变化可重开？ |
| 搜索位置 | 当前路径和最近可回退祖先在哪里？剩余未探索、受阻、暂缓方向分别是什么？ |
| 动作与结果 | 做过什么、对哪个目标、得到什么结果、产物在哪里？是否留下副作用或结果尚不确定？ |
| 继续与停止 | 下一项可执行动作、选择它的简短依据、依赖缺口、停止或重启条件是什么？ |

节点状态沿用[深度优先搜索](depth-first-search.md)的定义。未探索表示尚未开始；待验证表示已经提出假设但证据不足；暂缓表示主动后置，须写明原因和恢复条件。它们都不等于否定。受阻要写清缺少什么及如何解除；已否定要写清证据覆盖的版本、时间窗和条件，不能推广到未测范围。

共享节点保留一处可追溯的当前记录，其他分支引用其标识；记录中允许并列有来源、适用条件的竞争解释与未解决分歧。父前提或共享依赖变化时，写清哪些依赖结论已失效、哪些仍有独立证据；不能只改父节点状态。多个执行者可各写自己的分支文件，由明确的一位整合者维护共同入口、版本与分歧，避免相互覆盖。维护责任不赋予事实裁决权；无需引入锁服务或数据库。

证据应有来源、观察范围及必要的本地摘录或产物引用。只有链接而内容可能变化或无法再访问时，保留足以核验结论的非敏感事实、版本或快照；无法留存就标明恢复限制。观察、推断和未知要分开。记录简短决策依据即可，不要求逐字内部推理或隐藏思维链。

## 多个执行者如何共享与更新

共同入口沿用上述状态文件。协作需要时补明分支负责人、所依赖的节点、各方使用的输入版本，以及未解决分歧和跨分支线索；已有记录能表达就不增表格。分支结果须能定位到证据与适用范围，不能只有结论或一段脱离来源的聊天摘要。

重要变化应写清改了什么、依据是什么、影响哪些判断，再经已有授权渠道通知相关执行者。整合者在受影响分支的产物或下一动作中确认变化已被应用，或记录有依据的异议与待验证项。未确认时，将“未确认应用”作为依赖缺口保留；消息送达、对方回复“收到”、共享文件更新，均不能单独解除这个缺口。只暂停仍依赖失效前提的工作，其他分支按各自条件继续。

交接时检查接收者能否访问共同入口和所需证据。跨工具或模型无法共享文件时，可在授权范围内传递足以复核的材料及版本；不可访问的依据保留为缺口，不假装对方已读过。只共享本任务必要且获准的材料，不因协作扩大外部发送或资料访问权限。

普通进展无需逐条广播。候选解释可先独立形成再比较，已确认的事实变更、目标纠正和关键反证则应及时传递。分歧按来源、范围和区分证据维护；不要求一致同意才允许独立分支推进。恢复时优先检查尚未应用的关键变化，再沿有效前提继续。

## 何时写入并核验

1. **深入前：** 写入目标、授权、输入基线、初始树、当前路径和下一动作；实际重读确认文件存在且内容一致。
2. **关键变化后：** 取得改变判断的证据、更新目标或树、切换分支、发现阻塞或撤销依赖结论时，先更新文件再继续依赖它的探索。回退时保留失败依据和独立证据，写清回退位置及剩余分支。
3. **有副作用的动作：** 执行前记录目标和预期动作，执行后记录已确认结果。若中断后结果不确定，先核查实际状态，不能直接重放或把逻辑回退当作操作撤销。
4. **压缩、暂停、交接或收束前：** 更新当前路径、各类未决方向、下一动作、产物和缺口，再重读入口及变动部分，核验引用仍能定位。只在写入成功后报告已保存；保留最后一个可读状态，避免覆盖时丢失全部记录。

不必逐条记录无关工具调用。落盘对象是支持恢复的事实和决策状态。若文件缺失、写入失败或无合适的可写位置，说明具体限制并暂停依赖该记录的深入探索；可以继续不依赖缺失状态的工作，不能声称已持久化。

重读核验还要检查节点状态、当前路径和下一动作是否一致。更新或明确废弃旧待办、过期结论及重开条件；需要保留历史时标明已被什么记录取代。不能只更新总状态、确认文件存在或核对哈希，却让旧字段继续指挥恢复者。

## 从文件恢复

1. 从任务入口找到状态文件，读取当前状态及相关证据；不要凭残留印象重建已走过的路径。文件缺失或矛盾时明确缺口，先修复或重新取证，不捏造历史。
2. 对照当前请求和可访问的输入，复核目标、验收、授权、来源、版本与时间窗。历史授权记录是核对线索，不能扩大当前授权；明确仍有效的授权也无需重复询问。
3. 标出变化影响的节点与依赖结论。保留独立事实，对过期结论重新验证；仅在新证据、输入版本、机制或解除阻塞等条件实际变化时重开相关节点，并记录原因。
4. 恢复当前路径、回退祖先和未决集合。按已记录的范围避开仍被否定的路线；数据缺失的分支仍是受阻，不能假装已排除；暂缓分支按恢复条件处理。
5. 先核查未确认动作的实际结果，选取最有价值的授权内可执行动作。将本次核对结果、当前节点和下一动作写入并重读后继续。按根目标及用户明确的持续时间/停止条件收束；单节点失败或一批次完成不能代替根目标完成。已知树耗尽仍需检查扩树。

## 可复用的简短骨架

按任务删改字段，不必为单次简答填写。

```markdown
# 任务状态（更新时间/任务标识）
## 目标、验收、约束与授权
## 输入版本、来源与时间窗
## 逻辑树与节点
ID | 父节点/关系/共享依赖 | 假设与范围 | 支持/否定条件 | 状态 | 证据/结论 | 重开条件
## 当前路径与未决方向
当前路径/回退祖先；未探索；受阻及缺口；暂缓及恢复条件
## 动作与结果
目标/动作/已确认结果/产物；副作用；结果不确定项
## 下一动作与交接
动作/简短依据/停止条件；证据与产物路径；恢复限制
```

简化的落盘与恢复演示见[报表迟到排障](../examples/03-depth-first-search.md)。

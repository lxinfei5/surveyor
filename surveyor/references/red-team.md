# 反例审查 — 攻击自己的空间 + 按需红队

> 配套 `SKILL.md` 第 3 节。自己设计的空间，自己最容易看不见洞。本节是**主动攻击自己**的手法。

---

## 反例四攻（每个结构性交付至少过一遍）

### ① 双命中 —— 分区有重叠
- 构造几个**边界案例**，逐个问：它会**同时落到两个同级 owner** 吗？
- 命中 → 说明两个 owner 的分区**重叠**了。要么重划边界，要么声明**优先级/override** 关系，并写清谁先谁后。
- 问法：「这个案例，A 能接、B 也能接吗？都能 → 冲突。」

### ② 零命中 —— 分区有洞
- 刻意找**最不典型、最边角**的合法案例，问：它**落得到任何 owner** 吗？
- 落不到 → 分区有洞。要么补 owner，要么**显式**标 `residual / UNKNOWN + 原因`。
- 最危险的是**被表格静默省略**的案例 —— 它们不在表里，所以没人发现没覆盖。
- 问法：「有没有合法案例，被『其它』『看情况』这种词吞掉了？」

### ③ 边界切换 —— 切换条件写清了吗
- 对每个分区边界问：**哪个可观察条件**会让案例从一类**切到另一类**？
- 这个条件**写出来了**吗？是可观察的（不是「看情况」）吗？
- 例：静态页 → 需 JS 渲染，切换条件是「页面是否依赖客户端渲染」；公开页 → 登录墙，切换条件是「是否要求登录态」。

### ④ 失败穿透 —— fallback 偷换语义了吗
- 假设某个原生能力 / 登录态 / 数据源 / 依赖**不可用**，走 fallback。
- 关键一问：fallback 是否**偷偷改变了任务语义、对象身份、或证据等级**？
- 高频腐化：拿不到「真实登录态的数据」，就用「公网公开数据」**冒充**完成 —— 范围/身份/证据等级被偷换，却对外宣称「做到了」。
- 正确姿势：降级可以，但**终点要诚实**（`UNKNOWN + degraded_reason`），不许用更低等级的证据冒充更高等级。

## 按需红队（高影响、难逆的改动才用）

当改动**影响大、难回头**时，值得起一个**独立视角**攻击现方案：

1. **起干净上下文**：新起一个**没有现方案记忆**的独立 agent / 对话。
2. **只给两样**：终局目的 + 不可交换边界。**故意不给现方案**（避免被带偏）。
3. 让它**独立推一遍**：主矛盾是什么？逻辑轴怎么切？
4. **对照**：它的独立解，与现方案差在哪？差异处就是要复裁决的地方。

**三条纪律：**
- 这是**按需**红队，不是常驻编排 —— 不为每个小改动都起。
- **不以多数票替代裁决** —— 红队给的是「另一个独立推导」，最终仍由人/主 agent 拍板。
- 目的是**暴露盲区**，不是**证明原方案错**。

## 一句口诀

> **正例让你舒服，反例让你正确。** 一份只有顺滑正例、没有边界与失败反例的交付，等于没做过攻击测试 —— 打回去重做形状。

# 溯本清源：核验诉求和问题前提

本参考展开[主文](../SKILL.md)的第二个方向。

## 从表述追到结果

| 层次 | 要记录什么 | 例子 |
|---|---|---|
| 现象 | 用户实际遇到的情况 | 导出要等五分钟 |
| 解释 | 用户认为的原因 | 并发不够 |
| 手段 | 用户希望采取的动作 | 把并发调到三倍 |
| 结果 | 用户需要的可观察变化 | 一分钟内拿到完整报表 |
| 边界 | 不能交换的条件 | 数据不缺失，时效不降低 |

先查请求上下文，再查会改变判断的证据。已经明确的目标和授权，不重复询问。

## 哪些前提需要核验

优先核验能让方案整体失效的前提。常见前提包括：问题确实存在、原因已知、手段必要、验收指标有效。

目标含糊时，提出一个能改变动作的问题。例如，用户需要更早看到草稿，还是更早拿到完整结果？

可以用小样本呈现取舍。用户选择后，再更新根目标。不要要求用户先写完全部规格。

## 检查规则是否适合当前任务

除了核验用户提出的手段，也检查项目规则的适用性。先辨明本次是在形成理解、寻找问题、验证假设，还是实施交付，再读取会影响它的规则与环境条件。规则应按实际来源和范围解释：明确的用户要求与有效权限边界仍须遵守；面向发布的要求不应无依据地提前套到构想；历史惯例或输出模板可以提出调整建议。范围不清时说明具体歧义，不自行宣布豁免。

环境不匹配的判断须有证据。例如某条模板要求所有想法绑定已有模块，导致有材料依据的跨模块机制被删去；或者工具只能观察价格，研究却需要解释供需，输出因而静默换成价格代理。应定位具体条款或能力缺口、它保护的职责、被遗漏的内容，以及这怎样改变当前目标。约束多不等于不适合，缺工具也不证明相应机制不存在。

优先考虑局部且可恢复的适配：明确某条要求何时适用，允许探索保留候选问题和未知，补齐获准的上下文或工具能力，必要时建议在适合的环境继续。选择另一环境也须满足原有有效边界。已有授权足够则执行最小修改并核验；不足则准备具体修改内容、涉及范围和恢复办法，把未覆盖的修改留待授权，继续其他可推进工作。不要要求用户重复批准已经明确允许的调整。

适配后的验收对照原问题：能否形成原先被框架排除的解释或问题，同时正确区分证据与猜想，并在进入实施时恢复相应验证要求。不能只展示修改过的规则，也不能以“更自由”替代任务结果。现有记录应注明改变了哪些规则的适用范围与输入版本，供相关执行者和后续恢复核对，无需另建环境台账。

## 保住可操作表达中的原意

把想法转成指标、筛选条件、代码或试验时，对照原对象、适用条件与期望结果。说明这个表达能够回答什么、还不能回答什么；方便计算不是等价的证据。

例如，“让首次使用者独立完成任务”不能仅凭平均点击数下降来验收。点击数可以是诊断指标，也可能只反映熟练用户更快。应保留首次使用者、任务完成和无需帮助这些条件，核验代理指标与它们的联系。若用户明确只要比较点击数，则按该范围完成，不另行强加完整体验研究。

补充新要求时，复核原目标、约束与有效证据是否仍成立。能共存的要求一起保留；确有冲突才说明取舍，不能让最近一句话自动覆盖前面的重点。

跨 Agent 或模型交接时同样核对这些含义。摘要应保留会改变判断的对象、版本、条件与未知，能定位必要原材料；接收者取得任务不等于取得全部背景或额外授权。纠正传播后，检查接收方的实际结论与动作是否仍服务原目标，具体共享和核验方式见[本地状态与恢复](local-state.md)。

## 发现用户的解释不成立

1. 引用与该解释冲突的观察。
2. 说明它会怎样改变原方案的效果。
3. 提出仍服务原目标的替代路径。
4. 仅在涉及未授权取舍时请求裁决。

用户明确要求某项手段时，将它视为约束。建议改变约束可以，但不能静默替换。

用户的价值取舍与事实判断应分开。证据可以否定因果解释，不能替用户决定更重视速度还是质量。

## 让纠正改善下一次判断

用户的纠正可能在指出目标失真、证据不足、适用范围错误，也可能只是在表达本次偏好。先修正当前产物，检查哪些下游结论依赖被纠正的部分；事实有争议时保留证据核验，不将纠正一概视为已证明的因果解释。

值得迁移的是纠正所揭示的区别。例如，“页面很快出现，不等于完整报表已可用”可提示另一任务检查“写入成功，是否代表下游已读到目标版本”。二者都需要区分阶段完成与用户结果，但各自所需证据不同，不能照搬时延阈值或操作步骤。

提炼时写清混淆、适用条件和反例即可。进入新场景，先检查是否仍有相同的依赖关系，再选择当地的区分证据。若任务本来只要求页面占位或文件落盘，验收这些阶段就足够，不擅自加上下游要求。

下一次能否在未被提醒时识别同类区别，才是迁移的行为证据；一次成功仍只支持所测范围。有关判断可融入已有任务结论，避免逐条纠正积成新禁令或独立台账。当前任务的学习不自动授权改写全局记忆、其他项目规则或用户偏好。

## 给行动排主次

目标成立后，再问当前哪个可作用的约束最影响结果。证据不足时保留竞争解释，并选择能区分它们的验证。

比较做、不做、少做、替代方案的整体成本。包括执行、协调、验证、返工与后续维护。

新增结构应能解释其独有价值。删除结构也要核验依赖和保护职责。已有复杂度和能力缺失，需要不同的取舍。

若真实诉求改变，回到根节点复查验收。保留仍适用的事实，只撤销依赖旧目标的判断。

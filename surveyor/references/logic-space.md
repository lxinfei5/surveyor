# 逻辑空间 — 覆盖、互补、最小的完备性论证

> 配套 `SKILL.md` 第 2 节。第一性裁决定了**方向**，逻辑空间负责证明你**没漏、没重、没藏**。这是把「我觉得想全了」变成「我能证明想全了」的一步。

下文互斥、唯一 owner 与独占案例检验，限于需要唯一归属的分类、路由与责任划分。开放研究的假说和路线可以重叠、组合或共同成立；检验其依赖、区分证据与增量价值，不按覆盖重叠判冗余。

---

## 为什么普通 MECE 不够

MECE（相互独立、完全穷尽）只说了「不重不漏」，但**没说先按什么切**。最常见的假完备是：**把不同性质的东西并列成一栏，看起来穷尽，实则轴选错了**。

> 正确顺序：**先分类型（每个轴只回答一种问题）→ 在轴内做 MECE → 再把正交轴组合。**

例：设计一个「取数路由矩阵」。错误做法是直接把 `WebFetch / 浏览器 / 登录 Chrome / MCP / 搜索` 列成一排当槽位。它们混了三种性质：有的是**任务语义**（要拿什么）、有的是**访问前提**（要不要登录）、有的是**实现**（哪个工具）。先拆成三根正交轴，每根轴内再 MECE，才谈得上完备。

## 六问展开

### ① 原子对象
- 一行/一格/一项**究竟在分类什么**？
- 平台、页面、工具、状态、账号、数据类型……是不同对象，**不得偷混在同一格**。
- 自检：随便指一格，能用一句话说清「这格装的是哪种对象」吗？

### ② 同类型逻辑轴
- 每个轴只回答**一种**问题（要什么 / 访问前提 / 实现 / 环境 / 失败终点）。
- **先在轴内**查完备+互斥，**再组合**正交轴。
- 陷阱：把「任务语义」和「实现工具」列成同一排 → 这是两轴混一。

### ③ 关系形状
- 项与项是 **同轴分区**（同一维度的不重叠切片）、**正交叠乘**（不同维度自由组合）、**依赖**（A 依赖 B）、**优先级**（A 先于 B）、还是 **override**（A 覆盖 B）？
- 高频错误：把「B 借用 C 的访问通道」误写成「B 和 C 是同义的」。借道 ≠ 同义。

### ④ 唯一 owner 与空间闭包
- 每个**合法原子案例**都有一个**主 owner**。
- 落不到的，显式标：`N/A` / `UNKNOWN + 原因` / `未覆盖 residual`。
- **禁止**用「其它」「看情况」「等等」把零命中藏起来 —— 那些词背后往往就是洞。

### ⑤ 互补与最小
- 对每一项问：**有哪个具体案例，是只有它能覆盖、别的项覆盖不到的？**
- 答不出 → 标为冗余候选。判断删除是否改善目标、是否影响责任或必要验证；只有收益、风险与授权支持才删除，审计发现不自动触发整改。
- 两项回答**同一问题** → 合并，或显式声明边界/优先级。
- **例外（防误杀刻意冗余）：** 备援、双活、backup owner 这类**刻意的冗余**，按上一条会被误判死刑。它们须**显式声明为「冗余设计」**，不占同轴主 owner 名额——冗余在这里是特性不是缺陷，但要写明「我故意留了两份，为的是 XX」。

### ⑥ 相互干扰
- 标出子项间的**耦合、替代、侵蚀、长期副作用**。
- 局部最优若**破坏上游不变量**或**改写另一轴的语义** → 按第一性裁决**退让**。

## 怎么找正交轴（实操）

1. 把你能想到的所有「分类标准」先**脑暴平铺**（不管对错）。
2. 给每条问：它回答的是**哪一类问题**？（对象是什么 / 前提是什么 / 谁来做 / 在哪跑 / 失败了怎么办……）
3. **同类的归一轴**，不同类的就是正交轴。
4. 每根轴**单独**做 MECE；轴与轴**自由叠乘**构成完整空间。
5. 检验：换一根轴的值，会不会**强迫**另一根轴跟着变？会 → 这两轴不真正交，有依赖没拆出来。

## 覆盖论证（交付时要能说清）

> 这是**覆盖论证**，不是数学保证。开放问题空间无法真正「证明完备」——实际机制是**枚举 + residual 兜底**：尽力枚举，枚举不到的角落**显式标 residual**，而不是宣称「一个不漏」。

- **完备（论证）：** 尽力枚举后，不存在已知的、落不到任何 owner 的合法案例；未知角落已显式标 residual。
- **互斥：** 不存在同时落到两个同级 owner 的合法案例。
- **最小：** 删掉任何一项，都会有案例失去 owner（刻意冗余如备援已显式声明除外）。
- **正交与依赖：** 每根轴只回答一种问题；轴间是**正交叠乘**还是**约束/依赖**已分清（换一轴的值会不会强迫另一轴变？会→是依赖不是正交）。

> 一句口诀：**任意给一个合法案例，都能落到唯一一个 owner；任意删掉一个 owner，都会有案例变成孤儿（除非它是被显式声明的备援）。**

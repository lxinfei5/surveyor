# 深度优先搜索：节点、回退与扩树

本参考展开[主文](../SKILL.md)的第三个方向。

## 节点记录

复杂任务可保留简短的验证记录。简单任务无需为每个节点填写表格。

| 信息 | 用途 |
|---|---|
| 节点标识与父节点 | 明确回退位置及共享依赖 |
| 假设与适用范围 | 明确正在检验的命题 |
| 支持与否定条件 | 防止观察结果出来后随意改口 |
| 下一项区分证据 | 让验证能改变判断 |
| 证据及状态 | 区分观察、推断与未验证 |
| 剩余分支或重开条件 | 避免遗忘和无变化重试 |

每次验证只记录影响判断的观察。记录不包含模型的内部思维链。

## 状态不能混用

| 状态 | 含义 | 下一步 |
|---|---|---|
| 待验证 | 尚无足够证据 | 选择区分证据 |
| 已支持 | 证据支持当前范围内的假设 | 深入子条件或验证根目标 |
| 已否定 | 证据与假设冲突 | 回退并撤销依赖结论 |
| 受阻 | 验证所需条件不可取得 | 记录缺口并推进独立分支 |
| 已排除 | 与目标无关或违反明确约束 | 保留排除依据 |

“访问失败”不支持“内容不存在”。“没有发现证据”只有在检测能力足够时，才能用于否定。

如果关键证据只能来自受阻分支，最终结论仍须保留限制。其他分支成功不能自动填补它。

## 深入与回退

先按推进价值和区分价值排序。验证成本、风险与可逆性用于修正顺序。

沿当前分支持续深入，直到得到可用结果、被否定或受阻。全局新证据若否定上级前提，应立即中止依赖分支。

子节点失败后先回父节点。父节点若仍有替代路径，就进入下一条路径。

若失败的是父节点的必要条件，父节点也不成立。继续向上回退，直到最近可推进的祖先。

仅当父节点的子空间已充分覆盖时，才能从子节点全否定推出父节点否定。否则先检查遗漏分支。

“任一满足”的路线可用一个通过的候选解支撑目标。“同时满足”的路线必须核验全部必要条件。原因可共存时，需要检查组合与相互影响。

## 避免深度优先陷入单枝

每次细分都应更接近可观测的验证。如果只新增问题却不增加证据，回到上级更换拆分或取证方式。

成本上限、等待期限和目标时效可以限制单枝投入。不要因为一条路径暂时可继续，就永远搁置其他关键路径。

回到旧节点前检查失败原因是否改变。新证据、新机制或外部条件变化，可以支持重开。名称变化或相同请求的重复不支持重开。

## 根节点无剩余分支时

目标未达时，先把“当前树不完整”作为工作假设。按下表寻找结构缺口。

| 检查 | 能带来什么新分支 |
|---|---|
| 根问题把手段当目标 | 新的实现方式或不行动方案 |
| 只看内部执行阶段 | 触发、等待、交付、使用等遗漏阶段 |
| 时间或环境范围过窄 | 不同版本、时段、身份或部署条件 |
| 原因被错误设为互斥 | 多因素共同触发的组合分支 |
| 依赖被当成固定事实 | 验证依赖前提的上级分支 |
| 检测方式存在盲区 | 能看到原先遗漏现象的取证方式 |

扩树从未解释的观察或可疑前提出发。写明新增分支如何区别于旧分支，以及什么证据能验证它。

根问题变化时要复查受影响的节点。新树保留独立事实及旧分支的否定依据，避免重新走完全部旧路。

## 收束类型

- **已完成：** 根目标达成，必要条件和关键反例已验证。
- **约束冲突：** 证据说明现有要求不能同时满足。
- **受阻：** 明确缺少权限、输入、外部条件或预算。
- **待探索：** 仍有有价值的授权内路径，应继续推进。

已知树耗尽本身不属于完成，也不能证明无解。完成扩树检查后仍受限，需报告限制及重启条件。

验证通过后无需穷尽无关路线。不得把相同失败的重复尝试写成探索进展。

## 实际操作的副作用

逻辑回退只撤销判断。文件写入、消息发送和环境变更不会自动撤销。

验证优先采用只读观察或可逆小样本。需要恢复时，先检查实际状态和授权。不要为了回退删除仍有价值的证据或用户改动。

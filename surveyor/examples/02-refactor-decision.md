# 示例 2 · 重构决策 —— 「要不要把这个脚本 / 目录 / 阶段加进来」

> 演示 surveyor 如何用于**「加还是删」的防腐决策**。这是它最反直觉、也最有价值的一面：**默认有罪的是「加」。**

**任务：** 有人提议给系统加一个「自动编排脚本」，把原来靠模型临时完成的「发现 → 拆解 → 组合 → 浓缩」固化成一条流水线，号称「更稳定、更可复现」。

---

## 1. 第一性裁决

- **终局目的：** 产出**带分级置信的结论**；思考质量依赖**临场遍历逻辑空间**，不依赖预编程的固定路径。
- **当前主矛盾：** **这个脚本会把「约束形状」偷换成「编排思考」。** 一旦固化成 1→2→3→4，模型就从「真的想全」退化成「假装想全」（跑完流程即交差）。
- **不可交换边界：** 分析判断由当前大模型**临时完成**；约束以**自觉执行的心智形状**存在，不变成 schema / lint / gate / 硬流水线。
- **优先级依据：** 本次受「长期防腐」与「可逆性」支配。脚本**难逆**（一旦大家依赖它，就很难回到「模型自己思考」），且**增加第二套真源**（脚本逻辑 vs 模型判断，谁说了算？）。

**主矛盾判别器反事实：** *若只能做一件事，是「加脚本」还是「不加」？* —— **不加**。加了一旦错（编排取代了思考），整个「结论可信」的终局目的**整体失效**，且无法回退。

## 2. 逻辑空间

把「系统里的成分」按**正交轴**铺开：

| 轴 | 切片 |
|---|---|
| 成分性质 | 方法论（怎么思考）/ 客观事实（知识）/ 纪律（地板）/ 工具（怎么调） |
| 该不该存在 | 补不可复现的地板 / 显著减少长期耦合 / 都不占（→ 默认有罪） |

- **唯一 owner：** 「怎么思考」的 owner 是**当前会话的模型**，不是脚本。脚本若接管，就出现**双 owner**（脚本逻辑 vs 模型判断）。
- **互补最小：** 这个脚本覆盖的案例（固定路径的稳定执行），模型临时思考**本来就能覆盖** → 脚本**冗余**。
- **相互干扰：** 脚本会**侵蚀**模型的临场判断（大家开始信脚本不信思考）、**增加耦合**（改方法要同时改脚本）。

## 3. 反例审查

- **双命中：** 一个判断，脚本说一套、模型想一套 → 听谁的？**双 owner 冲突实锤**。
- **零命中：** 脚本没覆盖的**新问题形状**谁来处理？→ 模型。那脚本到底省下了什么？
- **失败穿透：** 脚本的某一步失败 / 数据缺失时，是**诚实报错**，还是**用占位值跑完**冒充「流程完成」？
- **边界切换：** 试着画「什么情况从模型自己想、切到走脚本」这条边界——发现**任何可观察的画法都破坏终局目的**：按「问题复杂度」画，复杂问题恰是最需临场遍历的；按「重复出现」画，重复不代表形状相同，固化路径反而错配。**能画出的每条边界都让「结论可信」变糟 → 这才是「脚本不该存在」的论证**（不是「边界模糊所以不该存在」——很多好东西边界都模糊）。

## 4. 交付形状

> **结论 + 主矛盾：** **不加。** 脚本会把「约束形状」偷换成「编排思考」，与终局目的（可信结论靠临场遍历）正面冲突。
> **长期账：** 增加第二套真源 + 双 owner 冲突 + 难逆。这三笔都是负的，远超「更稳定」这点眼前收益。
> **先修：** 维持「模型临时思考」为唯一 owner。
> **后修 / 暂不修：** 「可复现性」的真实需求，用**交付形状契约**（要求公开裁决与覆盖证明）解决，而不是用脚本固化路径。

## 5. break_condition 命中
- 把「稳定/可复现」当终局目的 → 套话，真正的终局是「结论可信」。
- 局部优化（脚本更顺）增加双源与耦合却不计长期代价 → 违规。

---

**一句话复盘：** 「删 > 加」不是洁癖，是**复杂度预算为负**的理性：每个新成分都要先证明「它补上了别人补不了的地板，或显著减了长期耦合」，否则默认有罪。这个脚本两项都不占。

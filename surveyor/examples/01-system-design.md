# 示例 1 · 系统设计 —— 给一个「多渠道内容抓取路由」做形状

> 演示五件事如何落地到一个**全新系统设计**。这是最典型的 surveyor 场景。

**任务：** 设计一个模块，把「结构化数据、公开网页、需登录的私域内容」统一抓取进来。

---

## 1. 第一性裁决

- **终局目的：** 拿到调用方真正需要的**证据**；拿不到时把**不可达边界**说清。*（不是「抓到更多」「调得更顺」——工具调用成功本身不是目的。）*
- **当前主矛盾：** **证据/任务语义能否在实现切换中保持不变。** 语义槽选错，后续工具越强、抓得越多，错得越完整。*（这是根基项：语义错了，一切下游全错。）*
- **不可交换边界：** 公网数据**不冒充**私域登录态数据；搜索摘要**不冒充**已读原文；工具不可用**不冒充**无信号；真实登录身份不被代理冒充。
- **优先级依据：** 证据语义正确 > 访问对象与登录态真实 > 失败终点诚实 > 运行环境效率 > 工具便利。*（本次主要受「证据语义」与「长期防腐」支配；新工具须先映射既有语义槽，只有出现无法归属的新任务语义才加槽。）*

## 2. 逻辑空间（先分类型，再轴内 MECE）

错误做法：把 `WebFetch / 浏览器 / 登录 Chrome / MCP / 搜索引擎` 列成一排当「槽位」——它们混了三种性质。

拆成**正交轴**：

| 逻辑轴 | 回答的问题 | 本设计中的形状 |
|---|---|---|
| 任务语义 | 要拿什么、按什么证据归类？ | 结构化 / 公网 / 私域搜索 / 登录态私域 |
| 访问前提 | 静态可取、需 JS 渲染、还是需真实登录？ | WebFetch / 无头浏览器 / 真实主浏览器 |
| 实现 | 哪个工具实际完成访问？ | 原生工具 / skill / MCP / Computer Use |
| 失败终点 | 不可用后怎样结束且不改语义？ | 槽内降级 / `N/A` / `UNKNOWN + 原因` / 明说做不到 |

- **关系形状（分清正交 vs 约束）：** 任务语义 ⊥ 访问前提（要拿什么，不限制访问前提的取值）；但**访问前提 → 实现是约束/依赖**，不是正交——把访问前提从「静态可取」换成「需真实登录」，实现轴上 WebFetch、无头浏览器就从合法变不合法，只剩真实主浏览器。*（用 logic-space 的正交检验：换「访问前提」的值，强迫「实现」的合法集跟着变 → 两轴不是正交，是有依赖没拆出来，须显式声明。）*「私域搜索」是任务语义槽，常**借用**「登录态私域」的访问通道（借道 ≠ 同义，结果仍按私域语义计）。
- **唯一 owner：** 每种任务语义一个主 owner 槽；拿不到显式 `UNKNOWN + degraded_reason`，不靠「其它」藏零命中。
- **互补最小：** 删掉「结构化」槽，结构化数值就失去 owner → 不冗余。

## 3. 反例审查

- **双命中：** 「私域搜索借登录态访问」时，证据 owner 仍唯一（归私域搜索槽）吗？→ 已声明，唯一。
- **零命中：** 「运行环境没有原生网页搜索」这种案例落得到 owner 吗？→ 落到「公网槽的多引擎 skill 降级」或显式不可达。
- **边界切换：** 静态页→JS/SPA、公开页→登录墙，两个切换条件都**可观察且写明**。
- **失败穿透：** 私域不可用后，**是否用公网公开数据冒充完成**？→ 红线，禁止；终点写 `UNKNOWN + degraded_reason`。

## 4. 交付形状

> **结论 + 主矛盾：** 路由按「任务语义」选槽、再在槽内选实现；当前主矛盾是证据语义在实现切换中不被改写。
> **覆盖/冲突：** 任务语义 ⊥ 访问前提（正交）；访问前提 → 实现是**约束/依赖**（前提收窄实现的合法集）；私域搜索依赖登录态访问通道（借道）。四根轴分类型铺开，但轴间关系有正交也有依赖，没有一概喊正交。
> **先修：** 语义槽唯一 owner + 失败穿透红线（上游、会污染一切下游）。
> **后修：** 各实现的优先级排序。
> **暂不修：** 工具调用的措辞与日志美观（具名：与语义正确性无关）。

## 5. 本例若犯这些错 = break_condition
- 从「我手头有 MCP 和 WebFetch」**倒推**槽位 → 倒推分类，重做。
- 把「登录 Chrome」和「私域语义」当同义 → 借道误作同义。
- 私域抓不到就拿公网搜索结果**冒充** → fallback 改写语义。

---

**一句话复盘：** 这个设计的「对」，不在于选了哪个工具，而在于**语义槽与实现解耦**——工具可换，证据语义不动。这正是主矛盾被钉住后自然推出的形状。

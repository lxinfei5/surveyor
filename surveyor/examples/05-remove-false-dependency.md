# 示例 5 · 删除错误依赖，而非增加交接流程

> 匿名示意情境，不代表已确认的历史事实或已完成迁移。

用户要把旧收藏迁移到可检索的本地目录。旧方案经 Windows 上的 DSH 导出，再交给另一个任务处理；现在已有直接读取导出文件的能力。目标是保留内容与来源关系，旧操作系统、工具和交接都只是手段。

区分历史条件与当前保护：假设已有证据确认旧导出完成，当前输入就是对应的冻结副本；同时确认身份、授权、读写隔离和备份保护独立存在。此时后续读取不必再等待旧环境上线或重复人工交接，可移除这条错误依赖。若来源身份、安全或授权仍未知，必须阻断依赖它的动作，不能把未知当成历史包袱删掉。

比较恢复旧环境、增加移交确认、直接处理冻结副本。直接路径若更低总成本，就先做小样本：保留原件，检查来源覆盖、文件哈希、重复与无法解析项，核验检索内容及来源回链。哈希用于证明文件一致，不代替语义正确或授权验证；无需因为旧方案用了 GPU 就照搬。

只有小样本支持新路径且操作获授权后，才扩大处理。完成约定范围，来源覆盖与异常清单可核对，必要验证通过，即结束。若新旧输出不一致，保留证据并定位差异；不以“步骤更少”宣布成功，也不自动新增整套交接制度。

# surveyor

> **先照清全局形状，再动手。**
> 一个 Claude Code skill：面对值得想全的问题，先**遍历逻辑空间**证明覆盖/互补/最小，再用**第一性原理**裁决主次与不可交换边界，用**反例**攻击自己，最后产出一份**别人能复核**的交付形状。

这是一个**思考方法**，不是工具、不是流水线、不取数。它约束你**必须公开哪些裁决与覆盖证明**，不约束你内部按什么顺序思考。

---

## 它解决什么问题

很多时候我们「觉得想全了」，但其实：
- 把**不同性质的东西并列**当成分类，看起来穷尽、实则轴选错了（假完备）；
- 把所有问题**平铺同权**，不敢点名一个真正上游的**主矛盾**；
- 从**手头已有的工具/文件倒推**设计，而不是从问题正推；
- 局部优化**增加了双源/耦合/未来迁移成本**，却只报眼前收益；
- 只有**顺滑正例**，从没拿边界和失败反例攻击过自己的方案。

`surveyor` 把「想全」从一种感觉，变成一套**可验证的形状契约**。

---

## 五件事（形状契约，缺一不可）

1. **第一性裁决** — 终局目的 / 当前主矛盾 / 不可交换边界 / 优先级依据。从终局目的一层层追问到不能再约简，敢用反事实判别器（*只能修一项修哪个*）钉死**一个**主矛盾。
2. **逻辑空间** — 原子对象 / 同类型逻辑轴 / 关系形状 / 唯一 owner / 互补最小 / 相互干扰。先分类型、轴内 MECE、再组合正交轴，证明**没漏、没重、没藏**。
3. **反例审查** — 双命中 / 零命中 / 边界切换 / 失败穿透，主动攻击自己的空间；高影响难逆的改动可起**干净上下文的独立红队**。
4. **交付形状** — 五件必须想完；默认按固定骨架输出：`裁决`（结论/终局/主矛盾/先修·后修·暂不修/边界）→ `关键支撑`（空间+反例）→ `可展开`，正确且低心智负担。
5. **break_condition** — 本方法自身的失效信号，命中任一即回去重做形状、不进入局部修改。

三条贯穿立场防退化：**整体 > 零件** · **删 > 加**（复杂度预算为负）· **约束形状 ≠ 编排思考**（不固化成 schema/lint/gate/硬流水线）。

---

## 何时用 / 不用

**用：** 结构设计、架构/方法评估、重构、分类/路由/目录/决策回路设计、多因素复杂问题拆解、「能做什么不能做什么」的边界判断、「该加还是该删 / 先修哪个」。

**不用：** 一句话能定、单点、可逆、影响面小的改动；纯执行类任务（命令怎么跑）；空间与主次已被更高层定好、你只需填局部实现时。

> 判据：**这个决定做错了会不会返工、会不会牵出第二个真源、会不会影响长期演进？** 会 → 用。

## 安装（Claude Code）

skill 本体在 `surveyor/` 目录（含 `SKILL.md` + `references/` + `examples/`）。

**方式一 · 项目级（推荐，随项目走）：**
```bash
mkdir -p /path/to/your-project/.claude/skills
cp -r surveyor /path/to/your-project/.claude/skills/surveyor
```

**方式二 · 用户级（所有项目可用）：**
```bash
mkdir -p ~/.claude/skills
cp -r surveyor ~/.claude/skills/surveyor
```

装好后，在会话里用 `/surveyor` 触发，或当 Claude 判断当前问题命中「需要先想全再想清」时自动加载。

**其它 runtime（Cursor / Codex / Trae / 等）：** 直接把 `surveyor/SKILL.md` 的内容作为规则/指令注入，或让模型在遇到结构设计类问题时打开它按形状执行。本方法**不依赖任何特定工具调用**，纯靠 markdown 自觉执行。

## 目录

```
surveyor/                    # ← 整个仓库就是一个 skill 目录（拷这个）
├── SKILL.md                 # 形状契约本体（唯一源）
├── references/
│   ├── first-principles.md   # 第一性裁决每问的 probing + 伪第一性识别
│   ├── logic-space.md        # 六问展开 + 怎么找正交轴 + 双/零命中排查
│   ├── red-team.md           # 反例四攻 + 按需红队操作
│   └── checklist.md          # 一页交付前自检清单
└── examples/
    ├── 01-system-design.md      # 系统设计：多渠道抓取路由
    ├── 02-refactor-decision.md  # 重构决策：要不要加编排脚本（删>加）
    └── 03-complex-problem.md    # 复杂拆解：团队延期先修哪个
```

`surveyor/SKILL.md` 是**唯一源**；references/examples 是按需点读的深层材料，不必预载。

## 出处

 distilled 自 **AStockOS V2** 工作区的架构纪律「第一性 · 问题形状 · 主次 · 逻辑空间 · 反例」——那是一个把这套思考方式当作常驻纪律在用的项目。本仓库把它抽成**跨域通用、零领域依赖**的形态，供任何项目复用。

> 一句话：**正例让你舒服，反例让你正确；先证明想全了，再动手。**
